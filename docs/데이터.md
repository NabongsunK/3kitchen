# 데이터 구조

나중에 RDB로 옮길 것을 전제로, 지금은 JSON 파일로 테이블을 관리한다.

## 규칙

| 항목 | 규칙 | 예 |
|------|------|-----|
| 테이블 | JSON 파일 하나 = 테이블 하나. 파일 이름 = 테이블 이름 (snake_case 복수형) | `characters.json` |
| 행 | 배열의 객체 하나 = 행 하나. 한 줄에 한 행 | |
| 기본키 이름 | 테이블약자(소문자 3글자) + `ID` | `chrID` |
| 기본키 값 | 테이블약자 + 4자리 순번. 0001부터 빈틈없이 | `chr0001` |
| 외래키 | 참조하는 테이블의 기본키 이름을 그대로 쓴다 | `stage_customers.chrID` |
| 다른 이름의 외래키 | 역할을 앞에 붙인다 | `arcs.bossChrID` |
| 배열 | 열에 배열을 넣지 않고 연결 테이블로 분리한다 | `recipe_ingredients` |
| 코드 | 사람이 읽는 고유값이 필요하면 `code` 열 (그림·아이콘 연결용) | `liubei` |
| 순서 | 연결 테이블의 순서는 `sortOrder` (레시피는 `step`) | |

새 행은 맨 끝에 다음 순번으로 추가한다. 순번을 당기거나 재사용하지 않는다.

## 테이블

| 테이블 | 약자 | 내용 | 행 수 |
|--------|------|------|------:|
| `factions` | fac | 세력 (한, 황건적, 군웅, 위, 촉, 오, 진, 남만, 재야) | 9 |
| `characters` | chr | 인물. 순번은 원작 첫 등장 순서 | 120 |
| `arcs` | arc | 원작 구간 (업데이트 단위) | 8 |
| `chapters` | chp | 원작 120회. 순번 = 회차 | 120 |
| `chapter_casts` | chc | 회차별 주요 등장인물 | 416 |
| `chapter_food_hooks` | cfh | 원작 속 음식·술·연회 장면 | 31 |
| `ingredients` | ing | 재료 | 8 |
| `recipes` | rcp | 요리 | 4 |
| `recipe_ingredients` | rci | 요리별 재료와 순서 | 11 |
| `stages` | stg | 게임 장 | 5 |
| `stage_customers` | stc | 장별 손님, 주문, 대사 | 17 |

## 관계도

```
factions ─< characters >─┬─ chapter_casts >─ chapters >─ arcs
                         │                      │
                         │        chapter_food_hooks
                         │
                         └─< stage_customers >─ stages >─ chapters
                                   │
recipes ─< recipe_ingredients >─ ingredients
   └──────────< stage_customers
```

## 코드에서 읽기

`src/data/index.ts`가 테이블을 읽어 게임용 모델로 조합한다 (예: `Recipe.steps`, `Stage.customers`, `Chapter.cast`). 게임 코드는 테이블을 직접 조인하지 않는다.

## 검증

```bash
npm run validate
```

기본키 이름과 순번, 외래키 참조, 고유값, 레시피 단계 연속성, 구간 범위를 검사한다. 새 테이블을 만들면 `scripts/validate.py`의 `TABLES`에 이름과 약자를 등록한다.
